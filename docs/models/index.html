models

Models get their columns from the database; you only write the behaviour.

app/models/post.iyi 
# Columns of posts (db/schema.json, kept up to date by `kurt db:migrate`):
#   id          Int64
#   title       String
#   body        String
#   published   Bool
#   created_at  Time
#   updated_at  Time
class Post < ApplicationRecord
  validates :title, presence: true
end

What it printed

db/schema.json
{
  "posts": [
    {"name": "id", "sql": "INTEGER", "type": "Int64"},
    {"name": "title", "sql": "TEXT", "type": "String"},
    {"name": "body", "sql": "TEXT", "type": "String"},
    {"name": "published", "sql": "BOOLEAN", "type": "Bool"},
    {"name": "created_at", "sql": "DATETIME", "type": "Time"},
    {"name": "updated_at", "sql": "DATETIME", "type": "Time"}
  ]
}

kurt db:migrate writes db/schema.json, and the build declares a typed property for each column, nilable when the column allows NULL. A property the model writes itself wins.

class Post < ApplicationRecord
  belongs_to user : User
  has_many comments : Comment, dependent: :destroy

  validates :title, presence: true
  validates :title, length: {maximum: 120}
  before_validation :strip_title
end
  • Associations. belongs_to, has_many and has_one, with dependent:.
  • Validations. presence, length, format, inclusion, uniqueness, then the model's own validate(errors).
  • Callbacks. In order, from before_validation to after_save.

Try it on your machine

Add a model that belongs to Post.

sh 
$ kurt g model Comment body:text post:references
$ kurt db:migrate

Kurt

Kurt is Turkish for wolf. It is an MVC web framework for iyi: models read their columns from the database, views are compiled with the app, and kurt build ships everything as one file.
