migrations

Change the database with plain SQL files.

db/migrations/20261126212518_create_posts.sql 
-- up
CREATE TABLE posts (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL DEFAULT '',
  body TEXT NOT NULL DEFAULT '',
  published BOOLEAN NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- down
DROP TABLE posts;

What it printed

kurt db:migrate · kurt db:status
   migrate  20261126212518_create_posts
      dump  db/schema.json
    update  app/models/post.iyi

  up    20261126212518_create_posts

The generators write SQLite, or PostgreSQL when DATABASE_URL is a postgres:// URL.

CommandDoes
kurt db:migrateruns what is pending, rewrites db/schema.json
kurt db:rollback [N]undoes the last N
kurt db:statuslists what has run
kurt db:resetdrops the SQLite database, migrates, seeds
kurt db:seedruns db/seeds.iyi

db/seeds.iyi writes a new database's first rows with the models, and runs again without doubles:

ada = User.find_or_create_by(email: "ada@example.com") do |user|
  user.name = "Ada"
end!

Try it on your machine

Write a migration and run it.

sh 
$ kurt g migration add_slug_to_posts
$ kurt db:migrate
$ kurt db:status

Kurt

Kurt is Turkish for wolf. It is an MVC web framework for iyi: models read their columns from the database, views are compiled with the app, and kurt build ships everything as one file.
