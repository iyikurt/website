Fast and readable, for people and their agents.

Kurt is an MVC web framework for iyi. You and the coding agent working with you follow the same rules: every file has a fixed place, and AGENTS.md writes those rules down. That means:

  • you write less code
  • the agent reads the rules instead of guessing
  • requests are answered by compiled code

Step by step

Build an application from scratch.

Thirteen steps from one real session. Each shows a command and its output, or a file it created. Scroll once to move one step.

  1. 01

    Create the application

    kurt new creates sixteen files: settings, a home page with its layout, a stylesheet, folders for the database and the tests, and AGENTS.md. The app can serve a page right away.

  2. 02

    The folder layout

    Models, views and controllers live side by side in app/. config/ holds the startup code and the routes, db/ the migrations and seed data, test/ the tests. Files in app/ need no module header or imports; the build adds them.

  3. 03

    Add a resource with a scaffold

    This command adds a Post with three fields. It creates nine files and updates two: a model, a migration, a controller with seven actions, five views, the routes and a test.

  4. 04

    Update the database

    kurt db:migrate runs the migration and saves the table structure to db/schema.json. It also lists the columns at the top of the model file.

  5. 05

    The model

    You don't declare columns in the model; they come from the database. Here you only write behaviour: for now one validation, later associations, callbacks and queries.

  6. 06

    The migration

    Plain SQL with an up and a down section. If DATABASE_URL points to PostgreSQL, the generator writes PostgreSQL instead of SQLite.

  7. 07

    The controller

    Seven actions. The set_post filter loads the record before show, edit, update and destroy; if it doesn't exist, the page returns 404. post_params decides which form fields reach the model.

  8. 08

    The views

    An .eiy file is HTML with iyi code inside. It is compiled together with the app, so a typo becomes a build error instead of a crash in production. <%= %> escapes what it prints.

  9. 09

    The routes

    One resources line creates a route for every action the controller has. kurt routes lists them all; /up is the health check.

  10. 10

    The test

    The test calls the routes directly, without a browser or a network connection, on a fresh database. It checks the list, a rejected form, a created post, a 404 and a delete.

  11. 11

    AGENTS.md for coding agents

    Coding agents such as Codex, Cursor and Copilot read AGENTS.md on their own. It describes the folder layout, the commands and the rules for each part. CLAUDE.md is one line that points Claude Code to the same file.

  12. 12

    Develop with kurt dev

    kurt dev rebuilds the app when you save a file and refreshes the open page. If the change doesn't compile, you see the error on your line and the previous version keeps running.

  13. 13

    Ship with kurt build

    kurt build compiles the app, its views and its migrations into a single 5.1 MB file. The server doesn't need iyi or the source code.

Performance

Why Kurt is fast

Interpreted frameworks redo part of their work on every request: loading code, finding methods, parsing templates. Kurt does this work once, when the app is built.

  • Native codeiyi compiles to machine code through LLVM before the app runs, and checks the types at build time.
  • Compiled templatesEvery .eiy view becomes code inside the binary, so rendering a page is just building a string.
  • All CPU coresThe server uses one thread per CPU core by default. Change it with -w.
  • Fewer database queriesincludes loads a list with its related records in two queries instead of one per row.

Kurt

Kurt is Turkish for wolf. It is an MVC web framework for iyi: models read their columns from the database, views are compiled with the app, and kurt build ships everything as one file.
